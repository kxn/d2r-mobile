# 池页区间枚举：当前 Mali CPU Profile 对应的有限优化

基于实际生产 `022d6254d9de565852fa22394b6403491db86707`，只改通用 Vulkan 后端的 `sync_used_pools()` 位图遍历。没有修改 NVN 命令、游戏模块、脏页代数、保护、拷贝、资源声明、GPU 依赖或完成顺序。

## 当前证据与收益范围

官方 Simpleperf 99Hz/8 秒和 Perfetto 数据在主工作区 `.local/logs/mali-022d625-fixed060-cpu99-sched-v1/`。实际 Mali-G710、原系统驱动、共享关闭、legacy ASTC copy 关闭、全量 ASTC4；3D 固定 0.60，输出 2772×1240，原营地。该窗口不是野外或持续温控验收。

翻译线程保留 745 个样本，`vk_draw_record` 包含调用为 53.83%，但自叶仅 4.83%。`shader_bindings_selected_impl` 包含 18.52%，其中 57 样本经纹理绑定，34 自叶，16 经描述符创建，13 经池地址解析。`sync_used_run` 包含 11.01%，其中 43 样本经脏页遍历、34 经保护、自己只有 4。不能把这些重叠百分比相加或视为全部可以消掉。

本次只处理 `sync_used_pools` 的区间枚举；其直接采样约 0.67%，预期是有限 CPU 指令节省，未证明整帧涨帧或降低温度。原算法对一个连续 1024 页范围进行 1024 次置位迭代；候选对同一个范围只迭代 16 个机器字，仍只发出相同的一个 `sync_used_run` 调用。

## 为什么等价

- 只读取已经归当前录制线程所有的局部 `bits` 副本；原位图、页上传戳、GPU 覆盖事实都不变。
- 一次取该字最低的连续一段 1 位，按递增页号消费；跨机器字仍由原来的 `first/end` 合并逻辑处理。
- 空洞仍在同样位置结束区间；最后一页的裁剪仍由原 `sync_used_run` 处理。GPU-owned upload mask 和共享分支选择原样保留。
- 每个实际回调的参数与顺序必须和旧逐位置位算法完全相同。因此脏页查询、保护、上传和所有之后的同步动作没有被跳过。
- 使用无符号进位清除连续段；特殊处理全 1 字，避免 `ctz(0)` 和移位 64。

新增成本是每段计算长度的一次 `ctz` 和数个整数操作。完全稀疏的单页段不减少迭代，会多做少量算术；密集或连续范围才节省循环/分支。没有添加缓存、堆分配、原子、锁、持久状态或环境变量。当前采集没有记录每个局部位图的段长分布，因此不能声称已经量化真实设备的总指令减少。

## 验证

`dm/gfx/vulkan/tests/bitmap_runs.c` 将实际 helper 与原生产逐位循环做回调序列差分，覆盖单个位、全部连续长度、穷举 16 位图案的多个位置、跨字和空字、GPU 覆盖掩码、尾部不足 64 页和确定性随机组合。398755 个用例使用 ASan/UBSan，比较完整区间参数、顺序、输入未被修改和候选迭代次数不增加。该工具没有计时/采样。

```sh
cc -std=c11 -O2 -Wall -Wextra -Werror -fsanitize=address,undefined \
  dm/gfx/vulkan/tests/bitmap_runs.c -o /tmp/d2r-bitmap-runs
/tmp/d2r-bitmap-runs
```

实际变更 `nvn_vk.c` 另用 canonical 022 的 Android NDK 28.2/ARM64/O3 原编译参数编译；这是编译检查，不是完整 APK/真机运行验收。不操作 ADB，不修改现有部署。
