# SGSR1-v3数值修正提案（仅离线，2026-10-28）

**先将整个SGSR颜色/滤波/权重/分母链明确设为highp，再保留基于已有采样值的异常回退；不进行新像素扫描、CPU统计或额外全屏pass。** 本文是[实际编译结果](ANDROID_SGSR1_ACTUAL_COMPILE_RESULT_2026-10-28.zh-CN.md)之后的离线提案，未生成/编译/部署v3，不影响正在进行的主线GPU实验。

实际12b的v2 NIR已经显示中心和gather颜色为float16、sum倒数为16bit，native有58个mad.f16。highp坐标修复没有覆盖这部分。v2仍只有编译资格，v1历史1.0图片也不能覆盖v2/v3。

## 最小改法

1. 在SGSR helper/滤波函数之前显式设置highp默认值，并将颜色、gather返回、mean、相对颜色差、sum/std、Lanczos权重、aWY累加、最终归一化与delta逐项明确为highp。包括函数参数和返回类型，避免调用边界又引入RelaxedPrecision。保持已经修正的坐标/Viewport/C7/gainUV与完整原fallback不变。
2. 直接检查**本来已经采到寄存器的值**：中心RGB、左gather及进入边缘分支后的其余gather若含NaN/Inf，返回失败；sum非有限或<=0时不取倒数；权重/累加不有限或aWY.x为0时不做除法；归一化结果或重建RGB不有限也返回失败。main收到失败便执行原 `originalComplete()`。不遍历整张纹理，不读回CPU，不增加为判定而做的采样。
3. 保留原最终乘gain顺序、原gainUV及alpha1；**不在gain之前加回上界1截断**。异常回退仍使用原采样与NaN/FMA语义，不自行合成另一套颜色结果。

这会增加少量寄存器值检查；异常走fallback时也可能重复取原五tap。它是显式成本，不承诺免费。可以证明为draw固定的尺寸/格式/UV资格仍应在接入资格层处理，不能为这份提案扩展CPU热路径或另加逐pixel诊断。暂不把统计、atomic或debug输出放进fragment。

## 必须区分的数值问题

- FP32降低half溢出/量化风险，**并不自动证明公式无奇点**；特别是权重归一化分母。先对0/非有限情况定义回退。若还要为“接近0”加阈值，需要根据权重绝对值之和及误差预算证明，或明确标为画质策略；不能随手填epsilon后宣称数学等价。
- 坐标有限与纹理采样值有限是两回事。历史R11G11B10中颜色确实大于1；该格式也允许更大值及非有限编码。一帧最高约1.9不能成为所有场景上界。
- 去upper-clamp只修复pre-gain高光截断，不等于SGSR已支持任意HDR。green代理、8/255边缘阈值、±23/255 delta、固定EdgeSharpness替代原k，仍是需要移动画面验证的质量策略。
- 相同full-register或max_waves摘要不能证明highp没有成本。后续有必要时再用现成原生编译输出检查实际精度、寄存器、纹理/UBO加载与依赖；不以静态指令数代替整帧工具结果。

复用独立review已有的具体反例：合法UFLOAT邻域可在0和64512之间交错，四个中心值均值约32256；12项绝对偏差的和可达到约387072，超过FP16最大有限值65504。Lanczos权重可约为64，`w*c`也可能超过FP16范围。它不是已观测到的游戏像素，而是推翻“格式值合法且坐标finite就足够”的数值反例；不需要重新抓帧或全图扫描。review也没有全域aWY.x非零证明，因此不能删掉分母检查。来源为 `.local/logs/snapdragon-super-resolution-pass-contract-v1/independent-contract-review/REPORT.zh-CN.md`，本轮没有重复建立该分析。

## 哪些仍可half

| 项目 | 判断 |
|---|---|
| 最终alpha=1、精确0/1掩码、小整数/二的幂等可精确表示常量的存储 | 可保留half表示；参与表达式时不能因此把需highp的运算降精度，通常没有单独优化价值 |
| 布尔/整数谓词的后端16bit表示 | 不属于颜色浮点精度问题，可保留驱动正常降低 |
| 最终乘gain并clamp到SDR之后的RGB | 将来可单独做有明确误差预算的候选；当前不列为已证明安全，更不把gain之前颜色压成half |
| 中心/gather颜色、mean、差分、sum/std、权重、aWY及除法 | v3先全部highp；在数值范围与移动画面证据齐备前不恢复half |
| UV、尺寸/倒数、floor、gather坐标、texel匹配、有效区域和gainUV | 保持highp，不能借最终RGBA8精度为坐标降级辩护 |

暂不为了少数常量再增加混合精度分支。先建立一个数值合同更清楚的基准，再按实际原生编译与GPU证据选择值得降精度的位置。

当前0.85的原c7/输入descriptor缺页仍然存在；下次必要的现成capture才补，不能串行阻塞主线，也不能用历史1.0或人工缩图代替。真正进入游戏前，还须确认输入格式/采样器/有效区域，完成v3真实输入的移动画面与整帧对照。本轮没有新的ADB、原生编译或画质/帧率结论。
