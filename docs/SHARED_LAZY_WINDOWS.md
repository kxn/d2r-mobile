# Experimental coherent shared lazy windows

`DM_VK_SHARED_LAZY_WINDOWS=1` (Android cold `--shared-lazy-windows`) is **off by default**. It requires fixed shared Pools, a nonzero window, the authenticated f830 Turnip build, and the existing startup import/overlap GPU byte gates. Unknown providers retain the original admission path. This is a host backend experiment, without game/driver changes or game-module qualification.

In the enabled experiment, **every** Pool registration additionally requires a complete committed RW alias of the original shared guest heap. Failure rejects registration; there is no mixed-Pool fallback or assumption that the original registration rules already proved this. Real Buffer/native imports must individually select HOST_COHERENT memory.

Only the draw entry explicitly opts into demand-only admission: it owns its nested lifetime scope without enumerating resources. Generic copy, transfer, dispatch and explicit range operations keep their original full collect/reserve before observation. Each real Buffer lookup runs the original mip/alias checks, then resolves an existing immutable range or imports only its rounded actual extent. Disjoint canonical nodes keep their original list/index contract. A crossing binding gets a separate immutable covering import. Old handles/origins remain unchanged until original Pool close has completed GPU/CPU effects and released references. Actual consumers still initialize/record access ranges and retain recording references; actual operation borrows are upgraded by the original pre-commit hook across internal submissions. Native cold binding retains identity under the original resource lock. Every actual native consumer also acquires metadata-only operation retention before acquire/alias callbacks, even when the per-chunk GPU stage ledger is already covered; current-plan Pool pointer hits need no additional lock. This does not publish GPU access early. No CPU dirty/ready, layout, upload, visibility or actual-consumer stage is cached or skipped.

Address-only VBO bindings have no finite fetch extent: they conservatively import the remaining Pool extent and retain its real access/reference. The original vertex dependency entry also expands this logical tail before checking writers, outside the resource lock; a Pool-tail empty binding remains no-access. They may need a large import. The optimization does not truncate them to one window or promise every legal input stays small.

From startup, named VkBuffer visibility proofs are disabled in this mode. Logical producer intervals continue to choose stages/accesses, using the original global VkMemoryBarrier fallback, including HOST publication. A producer may keep using an old handle after the resolver selects a newer covering handle. A named barrier on the latter would not prove the former's write. Coherency eliminates cache calls; complete logical coverage is still proved against Buffer/native import unions. Full-sync reference, destructive migration and quiescent union are incompatible and explicitly rejected.

Unique Buffer-covered logical bytes and summed Buffer import allocation bytes are reported separately in existing low-frequency game-state output. They exclude native-image imports (reported by existing native statistics) and are **not** PSS, external bandwidth or allocation savings. Overlapping imports name the same physical pages but consume additional BOs, GPUVA and driver heap accounting; f830 counts each import size without deduplication.

Initial bounds: 256 Buffer imports per Pool, 512 MiB summed Buffer imports per Pool and 2 GiB globally. Existing complete covers are reused. Budget exhaustion/import OOM is an explicit **incomplete candidate**, never a successful fallback, stable-release claim or hidden whole-Pool/mirror allocation. No early eviction is attempted. These limits require real-game coverage and memory review before any default-enable decision.

Host oracles use the existing software Vulkan backend, real Buffer writes/readbacks and Core/SYNC validation; `DM_SHARED_LAZY_ALIAS_FIXTURE` may override provider identity only in non-APP, non-Android test builds. This is not f830 hardware acceptance. Production APP builds must exclude that override and all fixture bodies. Native hardware/userptr byte, shader and lifetime acceptance and original-game validation remain required.

ON1 correction: ordinary B2T retile and mixed BC3/ASTC observation require the destination to have already been admitted. Generic admission cannot be skipped merely because a later Buffer consumer can import it. Invalid reserve batches still validate every range/Pool/prefix/native kind before any import. This change keeps draw-only lazy scope and all actual dependency/lifetime semantics. The initial a31 ON1 failure remains a failed experiment, not an accepted lazy runtime.
