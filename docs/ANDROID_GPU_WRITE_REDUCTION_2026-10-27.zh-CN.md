# Android 每帧 GPU 写入专项：清屏与既有后处理对照

用户要求优先减少每帧实际写入。本轮只使用连接的 Adreno 735，Mali 和 6GB 平板未使用。真实游戏沿原 ARM64 原生装载/HLE/NVN→Vulkan 路径进入营地；没有修改游戏模块、玩法、驱动或资源加工产物。

## 固定条件和测量范围

基准游戏输出 1968×900，固定 3D 比例 0.85，原 Android View 2358×1080，调用线程内翻译固定 CPU7，共享/native 资源、精确字节依赖、规划、异步完成开启，启发式 stream submit 关闭，Turnip f830 / prefer_sysmem。四项策略对照都使用同一个已发布 `3eec36b` APK，开启应用内 1968×900 缓冲候选，显式采用原 blit 出图，排除 shader-present 切换。

每次为独立冷启动，真实营地 tick≥2500、至少八个不同状态观测的管线数与特化数稳定后，使用原 Snapdragon Profiler 2026.9 GUI/设备服务的九项计数器，以及官方 Perfetto 8 秒完整游戏 Surface 间隔。各窗口特化数均为 32，管线计数在窗口内稳定；不同配置有不同管线计数，不能声称四组冷缓存内容完全相同。

字节单位为十进制 MB，硬件计数器是**全 GPU**，包含 Android UI/合成，不能直接归因于某个 NVN pass、独占 DRAM 或发热功耗。沿用原工具的时钟映射、验证和积分整理程序，没有新增运行时采样器或 GPU 计时器。B1 窗口附近额外读取过一次状态与进程列表，记录这项干扰，不将它写成完全无附加操作的窗口。

## 清屏修复独立于缓冲尺寸

此前原厂计数已经显示，原 View 缓冲约 65.5–65.6MB 写/帧，游戏尺寸缓冲保留细边约 59.1–59.4MB，游戏尺寸且铺满极窄边约 52.1MB。主要已知差异是输出缓冲大小和全图清屏，不能将整个差距归成着色器。

源代码 `3c88c4c` 将舍入细边的处理扩展到普通 View 尺寸缓冲：只有两个轴的总剩余像素均在 0～2 之间才铺满；真正的 letterbox 仍保持原矩形并清黑边。完整 blit 因而不再先执行整张 `vkCmdClearColorImage` 和重叠 transfer 写屏障。游戏输出/3D 渲染尺寸不变，输入继续使用实际归一化出图矩形。

这个修改消除的是可证明被后继完整 blit 覆盖的写入，不需要新缓存、逐帧环境变量检查、跨提交丢弃推断或游戏特判。它也不需要默认启用尚未完成恢复资格的 native-buffer-geometry。

新 canonical APK、ELF 和全部构建输入已校验并归档于 `.local/build/write-path-tiny-border-v1/`，真实游戏普通缓冲验证记录为 E1；测量和部署收条以同目录后继记录为准。

E1 已完成：native-buffer-geometry 关闭，原 View/交换链仍为 2358×1080，游戏仍为 1968×900/0.85，局部读取和炫光均开启。官方窗口为 **40.821 FPS、114.450MB 读/帧、55.362MB 写/帧**，GPU 约 497MHz。对照此前普通缓冲 A4 的 65.580MB，约少 10.218MB/帧（15.6%）；这是与先前稳定窗口的比较，不冒充本轮同 APK 的交错 A/B。没有在新 APK 添加一套只为还原这九行修改的热路径开关。

E1 已完成真实营地/画面检查、原 save2 和停止。相比本轮 A1 的游戏尺寸缓冲 52.429MB，普通缓冲仍多约 2.93MB 写入；因此缩小输出缓冲仍有独立价值，但不为此跳过恢复资格。E1 的 40.821FPS 与历史 A4 的 40.402FPS 只支持小幅变化，不报告成显著涨帧。机制明确的冗余全图清屏消除保留。

原有桌面配置是 **2358×1080 游戏输出、3D 0.75**，本来就没有这一组细黑边；不能声称玩家原有桌面设置也凭此节省 15.6%。该修复主要确保以后选择其他接近相同比例的输出尺寸时不再多写整张缓冲。用户配置没有被改成测试分辨率。

归档 APK SHA256 为 `54e724be74b6c227dd6f3dfa6f7a290a63de4396cee3cc285398e9d7835d50a7`，ELF 为 `8413677e2071eef8c5713f1d4583bbc3e9d0f59cfc5ccb6f37956fc8d0f45247`。桌面资格以 `publication/result.json` 两次真实无测试 extras 冷启动和 save2 为准；没有把一次基准截图当作普通启动验收。

## 恢复检查的证据修正

`.local/logs/native-buffer-lifecycle-v3/` 中，关闭 native-buffer 候选的参考组 BASE-OFF、BASE2-OFF 也未被辅助命令真正带回前台。截图是启动器，完整 Activity 信息为启动器 topResumed，官方 Perfetto 没有游戏 Surface 间隔，状态停止增长；仅有同一 PID 和 `am start` 成功返回不足以判定恢复。

这说明旧恢复验收失败不能直接归因于缓冲尺寸候选。它没有证明候选正常，候选仍默认关闭；普通清屏修复和冷启动写入试验不以该恢复判定为依据。

原始证据：`.local/logs/write-path-policy-v1/`，包括每组启动参数/实际状态、原厂 `.sdp`/数据库、Perfetto、时钟映射、完整 Surface 裁剪、截图、原 save2 与停止确认。计数整理为 `gpu-tools/comparison.json`。没有以截图 HUD 数字代替正式 FPS。
