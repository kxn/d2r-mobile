# Android native shell

The APK loads the original host as a shared library, executes offline-rewritten ARM64 game
instructions directly on the phone, and presents original NVN through Vulkan/SurfaceView.
No CPU emulation; see root AGENTS.md and the [port plan](../../docs/ANDROID_NATIVE_PORT_PLAN.md).

## Build and private data

```sh
source scripts/dev/env.sh
scripts/dev/build-android-native.sh --touch --tlsdesc
python scripts/dev/build-android-apk.py --tlsdesc
adb install --no-incremental -r .local/build/android-apk/d2r-native-tlsdesc-debug.apk
```

The no-preload variant uses native system TLSDESC, outputs to
`.local/build/native-touch-tlsdesc-rewrite`, and requires HOST_ABI=2. Its APK has no wrap.sh.
The original initial-exec debug path remains: build without --tlsdesc, using HOST_ABI=1
from `.local/build/native-touch-rewrite` and d2r-native-debug.apk. **Never mix hosts/modules;
the loader rejects incompatible ABIs.** Consumer importing and release delivery remain unfinished.

The APK contains no complete game, keys or game-derived shaders. App-private `files/runtime/` needs:

- `modules/`: matching three-module rewrite outputs and metadata.
- `RomFS/`: the user's merged extracted game.
- `shaders/`: complete validated offline Vulkan cache, currently 6931 modules.
- `romfs_overlay/`: original mobile overlay generated by build-original-assets.sh --overlay.
- `save/` and `temp/`: original host save and temporary directories.

Stage with adb push under `/data/local/tmp/d2r-native/`, then copy device-locally using run-as.
Do not stream module bytes through adb exec-out stdin; that transport is unreliable.
Save/quit and stop the application before replacing modules, then verify SHA-256. Keep game
inputs, signing keys, APKs, derived assets and saves ignored. Pinned zlib-ng is loaded only
for original asset-generation subprocesses; frozen PNG/table/metadata checks remain unchanged.

## Input and UI

Canvas/JNI use original dm_touch_controls.c. Platform glue follows front_ios.m for cursor,
item query/drag/double tap, binding, map, belt and player-count requests; game calls remain
in original host pumps. Original v4 HUD images, layout JSON and pre-rendered glyphs are
packaged directly; life/mana/experience/belt/player count come from original dm_hud_get.
Panels use direct touch by default; --ez touch_debug true shows development shoulder/D-pad
buttons. Physical controller and ADB key inputs remain available.

On slow frames, released UI fingers wait for the original hit/drop query answer instead
of the original frontend's 250 ms fallback. The actual release timestamp still determines
tap/hold duration. Unanswered queries are cancelled after five seconds or when superseded
by a new touch; they never fall through to an unclassified click, drop or sale.
Android's automatic menu direction pulses last one presented frame rather than three,
so slow frames do not turn a single row movement into the game's held-key repeat.
Other automatic keys keep the original duration.

Language uses the upstream Custom page (`lang_en` in `files/runtime/sw_custom.txt`):
1 selects English text and voice on the next launch, 0 selects Simplified Chinese.
The Android shell initializes the original custom-settings directory before mounting
saves, matching the iOS/Mac shells, so the original settings loader applies the choice.
Inventory, vendor panels and their text are rendered by the game through Vulkan;
Android draws the original touch controls and v4 HUD artwork through Canvas.

The original Custom page's Power saver setting now reaches Vulkan's target and the NVN
acquire pacer (30/60 tiers using the actual screen refresh). Actual same-process Apply
on/off is verified. Readonly frame_pacing records the target and effective acquire period;
it does not claim the GPU reaches the target. Display refresh-rate hints remain pending.


The optional upstream runtime extrapolation path is ported from nvn_rtex.inc and the
rt_* state machine. It alternates full world rendering with GPU history reprojection,
while keeping original skinned-unit/shadow/UI pass rules. Devices without shader stencil
export use an R8_UINT hole mask followed by a stencil-only draw. Default remains off.
Readonly runtime_extrap distinguishes candidates from actually encoded reprojections.

279259 GPU fixture checks pass with synchronization validation on lavapipe (both stencil
paths) and Mali (the two-pass path). They compare color/depth/stencil against an independent
scalar reference and exercise camera jumps, original pass roles and forced full frames.
The pass-role fixture checks the opaque result before synthetic postprocessing; these
counts do not establish final real-game compositing quality or performance.
Both native D24S8 and D32S8 are covered. Metal promotes NVN D24S8 to D32S8;
Vulkan preserves its precision and recognizes both as the original depth/stencil role.
Real-game opt-in now recognizes D24S8 main passes and encodes reprojections in camp and
area 2. Movement, area 1→2→1, inventory open/close and same-process 60→30→60 handoff pass.
More final-composite scenes and controlled performance comparisons remain unaccepted.
Same-PID HOME/save/Surface rebuild/resume continues encoded frames with unchanged HP.

Real-phone acceptance includes mobile character selection/camp entry, stick, world tapping/
pathfinding, stash, item selection/tooltip/drag followed by reload, scroll sale/buyback,
empty-slot binding followed by reload, portal 2→1→2, vital/experience/belt numbers,
player count 1→8→1 and minimap→fullscreen→minimap. Outdoor drag aim produced a real kill,
XP 21→54; a dropped starter potion was picked back up. Natural-drop coverage remains.
Thirty-five original enhancement modules are linked; linking does not accept all optional features.

Physical inputs use dm_pad_set; touch uses independent dm_input_set. Enter/Space confirm,
Escape returns, arrows navigate. Android editor uses original hle_swkbd.c UTF-16 limits/
UTF-8 conversion, with game-provided title/hints. Reconnect, multiple devices and all item/
skill gesture variants still need coverage.

## Diagnostics and acceptance

Start with `adb shell am start -n com.d2rmobile.nativeport/.MainActivity`.

- --ez run_game false: shell/TLS only.
- --ez validate true: require packaged Khronos synchronization validation.
- --ez run_vulkan_tests true: run original NVN/Vulkan fixtures and exit; needs private vulkan-fixture/.
- --ei trace_frame N: private per-draw GPU capture.
- --ei watch_type TYPE --ei watch_class CLASS: original unit watcher; CLASS=-1 cancels, singleTop updates it.
- --ez touch_debug true: additional development keys.
- --ez overlay_continuous true: previous continuous HUD redraw for same-process A/B; default redraws on painted changes while retaining display-rate input polls.
- --ez pipeline_byte_hash true: previous bytewise pipeline-cache hash for same-process A/B; default hashes words and still compares the entire key.
- --ez pipeline_prepare_reference true: rebuild the pipeline key/look up each draw for A/B; default directly reuses resolved static state. Validation launches additionally compare reuse against a rebuilt full key. These three controls accept singleTop updates; see scripts/dev/measure-android-render-toggle.py.
- --ez gpu_profile true: optional actual GPU region timing; disabled by default.
- --ez external_profile true: vendor capture mode; disables custom CPU timers/stats and submission/region GPU timing queries, retaining guest NVN queries, completion fences and input/state logs. Mutually exclusive with validate, gpu_profile and trace_frame. Launcher: --external-profile.
- --es game_res WIDTHxHEIGHT: optional cold-start output size, 16..4096; defaults to native Surface pixels.
- --ef scale_3d 0.5..1 and --ez fixed_3d true: forward the original 3D scale and dynamic-scale switch; launcher options are --scale-3d and --fixed-3d.
- --ez async_submit true: debug bounded submission overlap; launcher option --async-submit. Resources live per submission, with a cap of eight; pool mirror uploads use page bitmaps to wait for overlapping in-flight GPU accesses. The default remains the serial reference. Presentation also uses GPU acquire/copy/present semaphore dependencies, retaining waits for actual unfinished-resource reuse; CPU consumers such as packaged textures need further review; this is not complete asynchronous compatibility.
- --ef bright_k 1..4: debug-only forwarding of original DM_BRIGHT_K; default uses upstream dynamic exposure.
- --ez panel_freeze true: opt in to original DM_PANEL_FREEZE; upstream default remains off.
- --ez runtime_extrap true: opt in to upstream DM_RT_AB=1; default remains off.

Private native.log/tls.json/hid.jsonl/game-state.jsonl contain actual host events, TLS model,
original GetNpadState returns and original HUD/player/binding readings. Frontend intent is
not game-response evidence. android-game-key.py accepts a key or --tap X Y and waits for
real UI messages plus release samples. tap-unit.py uses original projections; walk-to.py
uses original stick direction math and observed positions, never teleportation/player writes.

The no-preload APK passed ordinary System.loadLibrary, three real modules, camp and touch
movement. Its process has no LD_PRELOAD; per-thread TLS offsets actually differ and isolation
passes. Native fixtures cover a thread predating dlopen, 64 concurrent threads, 200000 atomic
increments, signals, x18, x0/x1/LR, NZCV and SIMD preservation. The IE regression and incompatible
ABI rejection also pass. The same no-preload game process survived three HOME/Surface rebuild
cycles and resumed fresh world/binding snapshots. Release signing/configuration, 16 KB-page
hardware and extended stability remain.

Android now defaults to native Surface pixels following the original iOS display policy,
retaining handheld/docked selection and explicit size overrides. PHP110 passed actual game
and Surface output of 2772×1240, fixed 3D 1.0, English camp/inventory/movement/background
saving, and 769423 full pipeline-key checks without synchronization-validation errors.
Four normal windows without injection measured about 9.07 fps, still not smooth.
Old 1280×720 / 3D 0.60 records are a historical low-resolution baseline, not a controlled
speedup comparison. Presentation uses the driver extension; vendor profiling disables
custom timing, and unavailable metrics remain explicitly unavailable.

```sh
python scripts/dev/android-game-launch.py --external-profile --scale-3d 1 --fixed-3d --report .local/logs/native-launch.json
```

`game-state.jsonl` game_output/surface_output come from actual successful presentation
requests rather than launch intents. See the [submission lifetime audit](../../docs/VULKAN_SUBMISSION_LIFETIME.md)
for current serialization and the required ownership changes.

System Back uses original guest-frame pulses: B closes panels, PLUS opens the original menu from the world; a fullscreen map returns to the minimap first. Android 33+ uses the system Back callback, with the legacy callback retained for older devices. Real inventory open/close and map return have device evidence.

Original background saving commits from both active and paused gameplay. A moved item survived HOME, process termination and restart without Save and Quit. Discarded frames retain presentation numbering; present_sample_ns distinguishes fresh driver-derived timing after resume.

Wide-screen phone defaults follow iOS: native-pixel UI, 0.75 initial 3D scale and dynamic resolution with a 0.60 default floor. `--scale-3d 1 --fixed-3d` is a diagnostic override. Full narrow-tablet UI projection parity still needs separate verification.

The debug overlay averages existing actual-presentation intervals over about one second; feedback arrives about eight presents late. It adds no GPU query or timing sampler and is not a bottleneck profiler. The only displayed temperature is the event-driven battery-temperature broadcast, with no polling thread or ADB/file/shell/sysfs fallback. A public PowerManager listener caps rendering to the original 30-FPS tier at LIGHT/MODERATE and 20 FPS at SEVERE. After SEVERE, MODERATE keeps the 20-FPS limit; recovery to 30 requires thirty continuous seconds at LIGHT or below, and full release requires sixty seconds at NONE. It uses original saving/background suspension after 45 seconds at SEVERE or immediately at CRITICAL. This reduces sustained load; it is not a performance gain or proof that overheating is solved. Pausing or detaching unregisters listeners. Public thermal status may not cover every vendor protection policy; sustained gameplay must still verify timely protection. Battery temperature is not CPU/GPU temperature or evidence of the heat source.

python3 scripts/dev/android-game-launch.py --report .local/logs/launch.json cold-starts the existing character and waits for a startup marker matching the new PID, actual character-selection/HUD events and fresh player/binding/presentation observations. This avoids accepting the previous process log as startup evidence. android-game-key.py --host-event also accepts original host observations such as map-mode changes; default acceptance still requires UIMSG.

## Reproducible builds and deployment

scripts/dev/upstream-source.json pins the upstream baseline independently of local HEAD. Keep original ExeFS inputs separate from generated outputs; patched.bin is never an input. The full build invokes rewrite-native.py, which verifies image/side-table hashes, source/tool fingerprints and shared metadata even on cache hits. Damaged caches rebuild from original NSOs instead of patching old images.

```sh
source scripts/dev/env.sh
scripts/dev/build-android-native.sh --touch --tlsdesc
python scripts/dev/rewrite-native.py --source "$DM_ROOT/data/switch/3.3.94012/Update/ExeFS" --output .local/build/native-touch-tlsdesc-rewrite --abi elfdesc --rules touch-run-v4 --verify-only
python scripts/dev/audit-native-rules.py --bundle .local/build/native-touch-tlsdesc-rewrite --report .local/logs/upstream-audit.json
# Complete original background saving and stop the game before switching bundles.
python scripts/dev/deploy-android-modules.py --bundle .local/build/native-touch-tlsdesc-rewrite --report .local/logs/deployment.json
```

Outputs include rewrite-manifest.json, per-module provenance.json, upstream audits and on-device hash reports. Module deployment retains the previous generated bundle and does not process saves, RomFS or keys. All three default Apple images match pinned upstream byte-for-byte; Android audits distinguish platform branch relocations. Original fixtures cover identical clean rebuilds, automatic repair of damaged images/shared metadata, and rejection of missing gates, changed observers and rewritten inputs.

The default NVN occlusion implementation uses Metal-style pass spans. Debug Intent
`--ez query_per_draw_reference true` selects the previous per-draw query path and supports
singleTop updates for controlled measurements. It changes query grouping only; reports,
resets, draws and resolution retain their original semantics.
